<objective>
把"什么算 eligible 证据"从 inspect / prepare / inventory 三处各自为政的 SQL+Python 判定，收敛为唯一函数 `compute_eligible_messages`（新模块 `eligibility.py`），判定结果携带 `role` 字段（D-05：eligible 与 role 解耦，role 只决定进哪条轨）；`knowledge_inventory_items` 增加 `role` 列。完成后 inspect 与 prepare 对同一 canonical DB 给出同一 eligible 集合，Gate B 的"inspect 有 delta 而 prepare no_op"恢复为真实缺陷信号而非口径噪声。
</objective>

<context>
- 锁定决策：**D-05**（eligible = session 级 evidence_eligible + 内容清洗 + 长度阈值；role 只决定轨；三方共用同一函数）；**D-06** 的覆盖矩阵（41-03）依赖本 plan 的唯一口径作为分母。
- 口径差异清单（RESEARCH §4 精确表）：inspect（refresh_knowledge_units.py:121-128）= 裸 `role='user'` + `length>20`，无清洗无去重；prepare（refresh_knowledge_units.py:799-813 → build_inventory）= `role IN ('user','assistant')` + 清洗后 `>30` + content_hash 去重 + assistant 工具前缀排除；inventory（build_knowledge_inventory.py:80-223）同 prepare 但 items 无 role 字段。
- 重复定义待收敛：`SYSTEM_INJECTION_PATTERNS`/`strip_system_injections`/`is_meaningful` 在 build_knowledge_units.py:93-112 与 build_knowledge_inventory.py:38-54 两处各定义一份（正则内容相同）。

- 项目约定：新代码 import `personal_knowledge.application.*`；迁移脚本放 `tools/migrations/` 且默认 dry-run；所有排除/跳过路径必须带计数。

新建 `src/personal_knowledge/application/knowledge/eligibility.py`：
1. 定义 `@dataclass(frozen=True) class EligibleMessage`，字段：`evidence_ref: str`、`content_hash: str`、`role: str`、`session_id: str`、`source: str`、`agent: str`、`started_at: str`、`has_injection: bool`。
2. 定义 `def compute_eligible_messages(canonical_db: Path = AGENT_CONVERSATIONS_DB, *, roles: tuple[str, ...] = ("user", "assistant"), exclude_assistant_tool_prefix: bool = True) -> tuple[list[EligibleMessage], dict]`，语义逐项照抄 build_knowledge_inventory.build_inventory 的过滤链：
   - SQL 粗筛：`canonical_messages m JOIN canonical_sessions s`，`s.evidence_eligible=1 AND m.content IS NOT NULL AND length(m.content) > 20 AND m.role IN <roles>`，ORDER BY started_at DESC, canonical_message_id；
   - `strip_system_injections` 清洗后 `len(cleaned) <= 30` → 排除，计 `excluded_short`；
   - role=='assistant' 且命中 13 种工具命令前缀（`^\[Bash\]`、`^\[Tool:`、`^\[Thinking\]`、`^\[Read\]`、`^\[Edit\]`、`^\[Write\]`、`^\[Grep\]`、`^\[Glob\]`、`^\[TodoWrite\]`、`^\[Agent\]`、`^\[WebFetch\]`、`^\[WebSearch\]`、`^\[Skill\]`；仅当 exclude_assistant_tool_prefix=True）→ 排除，计 `excluded_tool`；
   - `_content_hash`（sha256 前 32 位，空白归一）去重 → 排除，计 `excluded_dup`；
   - 清洗后仅剩注入残骸（has_injection 且去尖括号后 ≤30）→ 排除，计 `excluded_injection_only`。
   - 返回 `(items, stats)`，stats 必含 `coarse_count` 与四个排除计数（失败不静默）。
3. 把 `SYSTEM_INJECTION_PATTERNS`、`strip_system_injections`、`is_meaningful`、`ASSISTANT_TOOL_PREFIX_PATTERNS`（新名，13 条正则从 build_knowledge_inventory.py:113-127 搬入）定义在本模块；`content_hash` 函数也搬入（名 `compute_content_hash`，保持 sha256[:32] 空白归一算法不变）。
</action>
