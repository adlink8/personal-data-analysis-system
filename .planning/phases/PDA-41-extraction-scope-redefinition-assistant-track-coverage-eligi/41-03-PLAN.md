<objective>
落地 source × role × pass 覆盖矩阵：每个 (source, role) 组合报告 eligible 消息数、已单元化数（证据并集口径）、按 pass 族（v1|/l2|/ku|/as|）分布、未覆盖原因三分类（abstained / terminal_failed / not_queued），ku| 命中标 grandfathered 豁免；矩阵作为 `pk-ku doctor` 的一个 severity=warn check 注册，新 source 首现 INFO、已知 source 连续零覆盖 WARN，**永不 FAIL**（不进 hard_fail_ids，exit code 不受影响）。让 zcode 1032 条 eligible 消息 0 KU 这类盲区系统报警。
</objective>

<context>
- 锁定决策：**D-06**（矩阵进 doctor；三分类未覆盖原因；WARN 不 FAIL——覆盖是观测问题不是正确性问题）；**D-04**（ku| 世代命中标 grandfathered，不计入未覆盖）。
- SQL 口径（RESEARCH §3）：source 取 `canonical_messages.source`；eligible 分母用 41-01 的 `compute_eligible_messages`（唯一口径）；已单元化 = `knowledge_unit_evidence` ∪ `knowledge_units.source_message_ref` 按 evidence_ref 去重（salvage 后 unit 合法持多 ref，必须用并集）；pass 族 = `substr(unit_id,1,3)`，与 StagingPublisher（knowledge_unit_pipeline.py:180）同口径。
- doctor 接入点：`run_doctor` 的 checks.append 序列（doctor_ku.py:604-633）；`hard_fail_ids`（:646-657）**不得加入** coverage check id；human 输出 `format_human`（:702-730）只打 WARN 行 top N。
- 历史比对分级：doctor 当次矩阵摘要写 `var/reports/analysis/ai_context/ku_coverage_latest.json`（只含 count/hash，隐私安全），下次运行比对；无历史时全部按首现 INFO。
- 性能：eligible 全量计算扫 canonical DB（~80k 消息），doctor 是日常命令——带 `--skip-coverage` 逃逸口 + source checksum 不变时复用上次结果。
- 依赖 41-01：`compute_eligible_messages` 是矩阵分母；与 41-02 可并行（矩阵把 as| 当普通 pass 族处理，as| 尚不存在时自然为零）。
</context>

<action>
新建 `src/personal_knowledge/application/knowledge/coverage_matrix.py`：
1. `def compute_coverage_matrix(unified_db: Path = UNIFIED_DB, canonical_db: Path = AGENT_CONVERSATIONS_DB, *, previous_snapshot: dict | None = None) -> dict`。
2. 分母：`compute_eligible_messages(canonical_db)` 按 `(source, role)` group by 计数（eligible_count）。
3. 已单元化分子（unified DB 单查询）：`SELECT DISTINCT evidence_ref FROM knowledge_unit_evidence UNION SELECT DISTINCT source_message_ref FROM knowledge_units WHERE source_message_ref != ''`，再 join 回 canonical 侧映射 (source, role)；同时按 `substr(unit_id,1,3)` 取 pass 族分布（v1|/l2|/ku|/as|，ku| 命中单独聚合成 grandfathered_count）。
4. 未覆盖三分类（对 eligible ∖ 已单元化的 ref 集）：
   - ref 出现在任一 run 的 `knowledge_run_items`，取最新 status='abstained' → abstained_count；
   - 最新 status='terminal_failed' → terminal_failed_count（另查 `knowledge_dead_refs` 是否已记录，未记录数计入 dead_ref_missing_count——失败不静默）；
   - 从未出现在任何 run items → not_queued_count；
   - role 决定轨：eligible 但属于另一轨的 role 不算未覆盖（按 (source, role) 行内自洽，天然满足）。
5. 行级分级：`previous_snapshot` 无该 source → level='info'（新 source 首现）；有历史且该 (source, role) 上次与本次已单元化均为 0 → level='warn'（连续零覆盖）；其余 level='ok'。
6. 返回 dict：`{"generated_at": ..., "source_checksum": ..., "rows": [{"source","role","eligible_count","covered_count","grandfathered_count","abstained_count","terminal_failed_count","not_queued_count","by_pass":{...},"level":...}], "totals": {...}}`——全 count-only，无原文（隐私安全）。
</action>

- 单测：previous_snapshot=None 时所有新 source 行 level='info'；传入上次零覆盖快照后同一 (source, role) 仍零覆盖 → level='warn'。
</acceptance_criteria>

<threat_model>
- 隐私面：矩阵与快照文件全 count/hash-only；assistant 轨内容（模型输出）只作为计数分母出现，任何 detail/日志/快照不回显消息原文或 evidence_ref 清单（ref 级明细只允许存在于单测 fixture）。快照白名单单测是防线。

- 性能面：eligible 全扫 ~80k 消息进 doctor 日常路径；checksum 缓存失效时单次计算可接受，但必须有 --skip-coverage 兜底，防止 canonical DB 异常膨胀时拖垮 doctor。
</threat_model>
