# Plan 17-03: End-to-End Answer Evaluation and Visualization

## Objective

验证检索提升是否转化为最终回答提升，并生成可审计、离线可打开的 HTML + PNG/SVG 报告。

**Decisions enforced:** D-03（retrieval/answer 分开评分）、D-04（本地脱敏报告）、D-06（judge 必须人工校准）。

## Tasks

<task id="17-03-01" type="auto">
  <name>Define replayable answer evaluation</name>
  <files>integration/scripts/evaluation/answer_eval.py, tests/test_knowledge_eval_answers.py</files>
  <action>五路 context 进入同一 answer generator；保存 prompt/model/config 与脱敏 replay inputs；规则评分 citation resolvability/precision/coverage、abstain、privacy。</action>
  <verify>python -m pytest -q tests/test_knowledge_eval_answers.py -k deterministic</verify>
  <acceptance_criteria>五路使用同 prompt/model；cache 可重放；citation/abstain/privacy 规则指标确定性通过。</acceptance_criteria>
  <done>相同缓存输入可重放；缺引用或引用越界明确失败；不把 retrieval hit 等同 answer correctness。</done>
</task>

<task id="17-03-02" type="checkpoint:human-verify">
  <name>Calibrate answer rubric and judge</name>
  <files>integration/evals/knowledge_units/answer_rubric_v1.md, integration/runtime/private_evals/judge_calibration_v1.jsonl</files>
  <action>冻结 correctness/faithfulness/helpfulness rubric；至少 30 cases × 5 paired answers 人工复核，对 LLM judge 做一致性校准。</action>
  <verify>输出 calibration artifact，包含人工标签、judge 版本、agreement/correlation 与分歧案例。</verify>
  <acceptance_criteria>报告 Spearman rho 与 Cohen's kappa；至少一项 >=0.7 且 privacy 无系统性分歧才可入 gate。</acceptance_criteria>
  <done>一致性 >=0.7 才允许 judge 进入 quality gate；否则只展示人工/规则指标。</done>
</task>

<task id="17-03-03" type="auto">
  <name>Build auditable visual report</name>
  <files>integration/scripts/evaluation/render_knowledge_eval_report.py, tests/test_knowledge_eval_report.py</files>
  <action>项目内生成 overview KPI、五路柱状图、Raw 相对提升、场景热力图、query win/loss、L2 类型/重复、质量-延迟-规模、历史趋势、gate verdict；每张图绑定 run artifact metric key。</action>
  <verify>python -m pytest -q tests/test_knowledge_eval_report.py</verify>
  <acceptance_criteria>每张图绑定 run_id/artifact/metric key；N/A 显示为 N/A；输出只在项目 analysis/evaluations。</acceptance_criteria>
  <done>HTML 离线可开；PNG/SVG 齐全；N/A 不绘为 0；secret scan=0；不再直接写 Desktop。</done>
</task>

<task id="17-03-04" type="auto">
  <name>Run full retrieval plus answer report</name>
  <files>integration/scripts/evaluation/run_knowledge_eval.py, integration/analysis/evaluations/</files>
  <action>对冻结 answer subset 运行五路 E2E，生成 run 目录与 latest pointer。</action>
  <verify>python integration/scripts/evaluation/run_knowledge_eval.py --config integration/evals/knowledge_units/eval_v1.yaml; python integration/scripts/evaluation/render_knowledge_eval_report.py --latest</verify>
  <acceptance_criteria>同一 run 内 retrieval/answer 结果齐全；报告可定位 case→ranked IDs→answer→score。</acceptance_criteria>
  <done>同一 run 同时展示 retrieval 和 answer 层，并可追溯 case→ranked IDs→answer→score。</done>
</task>

## Exit gate

报告必须清楚区分：KU 本体提升、Hybrid fallback 提升、最终回答提升；不得用单一总分掩盖任一关键失败。
