# Plan 21-01: Conversation Domain Migration + LLM Primitive Split

## Goal

First batch (D-03 ordering: conversation → graph → knowledge → memory, one batch per subdomain with a test gate after each). Split the cross-domain LLM hub `build_conversation_summary.py` (D-01), repoint the 6 cross-domain peers + 1 sibling at the new shared locations (D-02), then relocate the 8 conversation build scripts to `application/conversation/` and the 3 evaluate + 1 compare scripts to `evaluation/conversation/`, leaving re-export facades at every original `domains/conversation/` location (D-06/D-07). Build scripts first, then eval/compare (D-04). This is wave 1 because conversation is the most-depended-on center domain; its split must land before graph/knowledge/memory peers stabilize. The 4-batch ordering (D-03) is encoded in the plan dependency graph: 21-01 wave 1, 21-02/03/04 waves 2/3/4 sequential.

## Context references

- Facade pattern template: `src/personal_knowledge/retrieval/unified_search.py` (lines 18-58 show the `from personal_knowledge.<pkg>.<mod> import *  # noqa: F401` re-export style)
- Layer rule source: `governance/policies/architecture.yaml` lines 17-31 (conversation is `layer: domain`; `pipeline` = application may import conversation; `evaluation` may import conversation; conversation forbidden→pipeline/services/evaluation)
- D-01 hub source of truth: `src/personal_knowledge/domains/conversation/build_conversation_summary.py` — members `make_llm_client` (L280), `_chat_with_retry` (L312), `MAX_RETRY` (L38) are the generic LLM primitives; `summarize_chunk`/`parse_turn_summaries`/`SUMMARY_SYSTEM_PROMPT`/`SUMMARY_USER_PROMPT_TEMPLATE`/`PROMPT_VERSION` are conversation-specific helpers that stay with the build logic
