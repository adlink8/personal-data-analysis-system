<objective>
收口 Phase 42 两条 success criteria：(1) 端到端复核"同会话不再多份并存 + supersede 语义可查"；(2) 复核"重跑 sync 不产生重复、merge 结果跨运行稳定"。同时把首轮改键必然产生的 watermark 真实口径 delta（deleted_refs 突增，非伪 delta）在两条轨（committed / committed_assistant）上各走一次**受控** inspect→prepare 消化；给 `pk-ku doctor` 接入 warn-only 的双份率检查 `_check_session_dedup`；runbook 注记顺序约束与预期 delta，防止未来 Gate B STOP 反射误判。
</objective>

<context>
- ROADMAP Phase 42 success criteria：1）同会话内容增长被识别为同一 canonical session 更新，同会话不再多份并存，旧副本有明确 supersede 语义；2）全量重建幂等，重跑 sync 不产生重复 session/message，merge 结果跨运行稳定（含 legacy 代表行确定性）。
- delta 定性（RESEARCH §5.2）：`compute_source_checksum` 含 schema hash + 逐条 content hash，42-01 必然使其变化 → `source_changed=true`。new_refs≈0（cm id 未重铸）；deleted_refs = 被 supersede/合并副本曾入 inventory 的 eligible ref（上限 2,334，实际远小——eligibility 的 content_hash 去重本来只放行一份）。**这是真实口径修正，不是伪 delta**，与 41-RESEARCH R6 同型。
- AGENTS.md KU 硬规则 3 的 STOP 语义仅针对"inspect 有 delta 而 prepare no_op"的真异常；本 plan 明确区分两者。
- doctor 立场（PATTERNS「文件 4」）：双份率是**观测口径不是正确性 gate**——ok 恒 True、severity='warn'、不进 hard_fail_ids、异常吞掉不阻断。
- 红线：不改 eligibility SQL；不硬删 KU 行（lifecycle 流程消化 deleted_refs）；AgentsView live 只读；不重铸 cm| id；本 plan 不含 KU 重抽（extract 及之后不在范围）。
</context>
