<objective>
42-01 重建后，落在被 supersede/被合并旧副本上的存量 unified DB ref（实测量级：knowledge_unit_evidence 40 个 distinct ref + knowledge_units.source_message_ref 89 个 + knowledge_inventory_items 连带）需要一次性重映射到保留副本的同内容消息（D-03：content_hash 对齐为主、ordinal 就近为辅）。canonical 侧已由 42-01 的 builder 天然收敛，本 plan **只写 unified DB**。脚本形态照抄 tools/migrations 既有标准：默认 dry-run、--write 先备份、单事务、幂等 no_op、统计报告；映射失败的 ref 保持原值入孤儿报告，并与 756 个存量静默孤儿（R4 债）分列基线（D-05：失败不静默）。
</objective>

<context>
- 锁定决策：**D-03**（supersede + ref 映射，映射不了的记孤儿报告；"ordinal 对齐"实际落地 = content_hash 对齐为主、ordinal 就近为辅——legacy ordinal 是自计数体系，与 AV ordinal 不可直接对齐，RESEARCH §1.2）、**D-05**（全部失败路径计数）。
- 影响面已实测（RESEARCH §1.3）：40 + 89 个 ref 落在 6 组双份会话，95.1% 消息 content_hash 可与保留副本对上（≈114 条对不上，R5，其 ref 保持原值——superseded 副本仍可回查，resolve=ineligible 属预期）。
- 关键架构事实（RESEARCH §3.1）：canonical 每次 sync 全量 DROP+重建 → **对 canonical DB 的任何 UPDATE 都会被下次 sync 无痕冲掉且违反"canonical 只由 builder 产出"**。本脚本读 canonical 一律 mode=ro。
- 42-01 重建后，6 组双份中 legacy 侧消息（id 由 `_norm_id("cm","legacy",<session_id>,<event_index>)` 铸出，**实际形态是 `cm|<sha256[:32]>` 不透明串，字面不含 "legacy"**，builder :604/:125-127）可能不再存在于新 canonical（强匹配合并后以 AV 消息为准）——原消息 content 需从**旧代 canonical 备份库**取。builder 的 backup 是**单代滚动**（:646-648，每次 --write 换代），故 old DB 必须用 42-01 task 6 固化的 `var/backups/agent_conversations_pre42_<ts>.sqlite`，不可依赖滚动 backup。
- 红线：不写 canonical；不 DELETE 任何行；报告只含计数与 ref id，不回显消息原文；两类孤儿严禁混报（42 映射失败 vs 756 存量 cm id 漂移债）。
</context>

3. 扫描三表全部 `cm|` refs：`knowledge_unit_evidence.evidence_ref`、`knowledge_units.source_message_ref`、`knowledge_inventory_items.evidence_ref`，逐 ref 分类（canonical 连接一律 `mode=ro` + busy_timeout）：
   - `resolved_active`：可解析到 lifecycle IN (NULL,'active') 且 evidence_eligible=1 会话的消息 → no_op 计数；
   - `resolved_superseded`：解析到 lifecycle='superseded' 会话消息 → 映射目标 = `superseded_by_canonical_id` 指向会话中 **cleaned content_hash 相同**的消息；一对多时取 ordinal 差最小者；
   - `unresolved_dup_member`（主迁移路径，40+89 ref 的归宿）：**禁止用 ref 字面前缀/子串判源**——cm| id 是 `cm|<sha256[:32]>` 不透明串（builder :604 先 `_norm_id("cm","legacy",sid,idx)` 拼串再哈希，:125-127），没有任何 ref 字面含 "legacy"。判据为三条同时成立：(a) **新 canonical 查无此 id**；(b) `--old-canonical-db` 的 canonical_messages **存在该 id** 且 `source='legacy'`（或等价 `source_message_ref LIKE 'legacy:%'`，builder :605）；(c) 经旧行 canonical_session_id → 旧库 session_source_links 取 legacy 的 source_session_id（或直接从 source_message_ref 解析出 `<sid>`）→ 新库 session_source_links(match_method='source_mapping') 命中某 lifecycle='active' 会话。三条全中 → 取旧行 content（cleaned content_hash），同法映射到该 active 会话消息；
   - `remap_orphan`：以上映射失败 → **ref 保持原值**，计入孤儿报告（R5，预计 ≈114 条消息对应的 ref 子集）；
   - `preexisting_orphan`：新 canonical 查无此 id 且 **不满足 unresolved_dup_member 判据 (b) 或 (c)**（old DB 查无该 id、或非 legacy 来源、或 source_mapping 链路对不上 active 会话；R4 的 756 存量 cm id 漂移债）→ **只计数呈现，不处理**，并与 baseline json 的 `evidence_refs_unresolved_baseline` 打印对账行。
4. plan/apply 分离：`plan_remap()` 产出 {表 → [(old_ref, new_ref)], 分类计数}；`_print_report()` 打印；`apply_remap()` 仅在 --write 下于**单事务**内执行三表 UPDATE（含 knowledge_unit_evidence 复合主键冲突时的 INSERT OR IGNORE + 旧行保留策略按既有表约束处理，冲突计数不静默）。--write 前先 `_backup_unified_db`（shutil.copy2 → `var/backups/personal_system_<ts>.sqlite`）。
5. 幂等：重跑时 resolved_superseded + unresolved_dup_member 均为 0 → 打印 `no_op` 退出 0。结尾 `print(json.dumps({...}))` 摘要必含键：`write`、`remapped_evidence`、`remapped_source_ref`、`remapped_inventory`、`remap_orphans`、`preexisting_orphans`、`no_op`。
