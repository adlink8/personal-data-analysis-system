<interfaces>Renderer calls window.harness only. Navigation lists use safe IDs/labels/status; a `ConversationThreadView` comes only from the named canonical Python projection route and contains normalized user/assistant display messages with stable message ID, role, display text, created time, source/evidence ref, pagination/truncation and freshness. Empty/stale/partial/paginated states are explicit. The selected view is ephemeral renderer memory: no disk/localStorage body persistence, and logs/receipts/telemetry retain IDs/counts/checksums/status only. Turn view: answer, evidence, freshness two legs, limitations, selected Skill side-effect/status/receipt count, safe SQLite card, cancelTurn({taskId})/resumeTurn({taskId})/reconcileTurn({taskId}) state. `reviewCandidate()` accepts only `{candidateId, action, expectedVersion, editedPayload?, editedPayloadChecksum?, explicitConfirmation?, confirmationToken?, conflictDisposition?, feedbackId?, taskId, binding, idempotencyKey}` and can reach only fixed `candidate.review`; its safe states/receipt are rendered without private content. `getPersonalModelProjection({scope,binding,taskId,idempotencyKey})` reaches only fixed `personal.model_projection.get`, returns a derived/versioned/provenance/freshness/confidence/time/support/conflict/supersession view, and the renderer cannot supply a draft, ignored Candidate or context text. Projection view: derived label/version/confidence/valid time/freshness/support/conflict/correction. The minimal command palette has a fixed in-renderer action map only: `receipt.open` opens the selected safe receipt drawer, and `proactive.manage` opens the existing proactive settings drawer; it never forwards arbitrary command IDs or payloads. Proactive view uses getProactiveState({projectScopeId?}), updateProactiveControls({scope,category,enabled,quietHours}), dismissProactive({itemId,reason?}) and undoProactiveDismissal({feedbackId}) for deterministic event status, global/project/category controls, quiet_until, one cluster card with merged_count and evidence drilldown, and append-only dismiss/undo feedback.</interfaces>
