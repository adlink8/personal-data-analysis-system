# Plan 22-01 — Lifecycle reconcile (dry-run first)

## Goal

Ship `pk-ku reconcile` that **detects** subject-level conflicts / superseded candidates and reports them **without writing** by default. Optional `--write` only updates `lifecycle` / `supersedes_id` (never DELETE).

## Tasks

1. **Model**
   - Define reconcile actions: `keep_current`, `mark_superseded`, `mark_conflict`, `noop`.
   - Input: subject scope / since date / run_id filter.
   - Output artifact JSON under `var/reports/analysis/ai_context/` (gitignored runtime).

2. **Rules (v1 minimal)**
   - Same `subject` + same `unit_type` + high answer similarity → propose merge lineage (newer `generated` supersedes older).
   - Contradictory answers (LLM or heuristic) → `conflict`, both retained.
   - Evidence-deleted already handled by refresh deprecated path — document integration only.

3. **CLI**
   ```text
   pk-ku reconcile [--subject S] [--since YYYY-MM-DD] [--dry-run|--write] [--max-subjects N]
   ```
   Default dry-run. Fail-closed if `--write` without confirmation flag `--i-know`.

4. **Tests**
   - Unit: action selection on fixture units.
   - Integration: temp SQLite; write mode never reduces row counts.

## Acceptance

- [ ] Dry-run produces counts + sample actions, zero DB writes.
- [ ] Write mode: only lifecycle/supersedes columns change; COUNT(*) stable.
- [ ] Documented in `docs/runbooks/ku-incremental.md`.
- [ ] pytest green for new tests.
