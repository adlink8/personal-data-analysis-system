# Phase 13.5 上下文：AgentView 会话源集成

<domain>
## Phase Boundary

把 `$HOME\.agentsview\sessions.db` 接入现有个人数据系统，形成一个可复现、隐私安全、能与旧 Agent 数据去重的 canonical conversation evidence 层。

本阶段只负责“上游事实源与规范化证据”。它不生成 knowledge units，不切换知识检索默认 collection，也不让 LLM 直接判断长期记忆。

</domain>

<decisions>
## Implementation Decisions

### D-01：阶段必须与 Phase 14 分开

- AgentView 是上游数据源和数据治理问题；Phase 14 是下游知识蒸馏与检索评估问题。
- 执行顺序固定为 `Phase 13 → Phase 13.5 → Phase 14`。
- 使用 13.5 而不是把现有 Phase 14 改号为 15；项目已有 `05_5` 小阶段先例，且这样能避免大量引用迁移。

### D-02：源数据库永远只读

- `sessions.db` 是 AgentView 正在写入的 WAL 数据库，当前 `user_version=59`。
- 连接必须使用 SQLite URI `mode=ro`、`PRAGMA query_only=ON`，不得迁移、建索引、VACUUM 或写入源库。
- 长时间导入前使用 SQLite backup API 取得一致快照；禁止直接复制 `.db/.db-wal/.db-shm` 三个文件拼装快照。

### D-03：建立安全规范化层，不让下游直接查询 AgentView

- 生成 `Agent/structured/db/agentsview_normalized.sqlite`，通过 staging 文件和原子替换发布。
- 规范化库只保留下游需要的会话、消息、关系、工具元数据、用量和 lineage；不复制 AgentView 的缓存、定价、insights 或 FTS 内部表。
- 再由 legacy `agent_data.sqlite` 与 `agentsview_normalized.sqlite` 构建 `Agent/structured/db/agent_conversations.sqlite`，作为下游唯一会话事实入口。

### D-04：隐私与证据资格是结构化字段

- 永不复制 `thinking_text`、用户邮箱、用户 ID、原始 `input_json`、原始 tool result content、insight prompt/content。
- `secret_leak_count > 0` 或存在 `secret_findings` 的会话默认 `evidence_eligible=0`，只保留最小审计元数据，正文不得进入摘要、向量库或 knowledge unit。
- `excluded_sessions` 和未来 `deleted_at` 必须传播为 tombstone；不得因下游已有副本而继续可检索。
- system message 默认排除；sidechain/subagent 消息保留关系，但默认不作为用户个人事实证据。

### D-05：说话者来源不可丢失

- 用户偏好、习惯、个人事实只能由 `role=user` 的证据直接支撑。
- assistant、subagent 和 tool output 可以支撑“项目过程/技术结果”，不能单独证明用户偏好或现实事实。
- canonical message 必须保留 `role`、`agent`、`relationship_type`、`parent_session_id`、`source_session_id` 和 source ref。

### D-06：旧数据去重采用 source lineage，不靠文本模糊匹配起步

- 当前 AgentView 498 个非空 `file_hash` 中有 404 个与旧 `source_files.sha256` 重叠；这些必须折叠成同一 canonical session。
- 优先匹配顺序：`file_hash` → 明确 source mapping → 稳定会话签名。
- 没有强证据时保留为独立会话并进入 review report，禁止用宽松相似度自动合并。
- 重叠时优先采用 AgentView 的结构化消息/关系表示，但保留 legacy raw refs。

### D-07：先 shadow，后 cutover

- 新 canonical conversation store 必须先与现有链路双跑。
- 只有计数、去重、隐私、来源回查和下游回归 gate 全部通过，才把 conversation summary、integrated system 和 evidence bundle 的默认输入切到新 store。
- 旧 `agent_data.sqlite` 保留为 fallback，不删除。

### the agent's Discretion

- staging 临时文件的具体命名。
- 小批量写入 batch size。
- 稳定会话签名的具体哈希拼接格式，但必须版本化并有测试。

</decisions>
